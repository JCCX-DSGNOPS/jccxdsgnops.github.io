Introduction

Getting Started

NODO is structured as a layered architecture: primitives feed semantic tokens, tokens feed components, and components compose into patterns and templates.

Primitives

16 color ramps with 10-step scales, spacing units from 0 to 60px, radius from 4px to pill, and 9 opacity levels. These are the raw building blocks.

Semantic Tokens

292 scheme tokens map primitives to meaning: primary, surface, error, success, warning, and more. Every token has light and dark mode definitions.

Components

140+ component sets across 13 categories with 3600+ total variants. Over 30 components include anatomy documentation pages.

Usage Guidelines

Best practices for applying tokens and components correctly across product surfaces.

Do
Primary
Secondary

Use semantic color tokens for all interactive elements. Primary actions use filled variants, secondary actions use outlined variants.

  • Use primary for the most important action on screen
  • Limit to one primary button per view
  • Use outlined or text buttons for secondary actions
Don't
Delete
Save
Submit

Avoid using multiple filled buttons with different colors in the same action group. This creates visual noise and confuses hierarchy.

  • Never place multiple primary-weight buttons together
  • Avoid using error color for non-destructive actions
  • Don't use hardcoded hex values instead of tokens
Do
Email user@email.com
Name John Doe

Use consistent spacing tokens across form elements. All inputs should use the same vertical rhythm for visual alignment.

  • Use spacing/4 (16px) between form fields
  • Use spacing/6 (24px) between form sections
  • Use spacing/2 (8px) between label and input
Don't

Don't mix radius tokens inconsistently within the same context. Related elements should use the same radius value.

  • Cards in a grid should share the same radius token
  • Use the radius scale intentionally for hierarchy
  • Never use arbitrary pixel values for border-radius

Guidelines

Patterns

Reusable interaction and visual patterns that ensure consistency across all NODO components.

State Layers

Interactive elements use semi-transparent overlays to communicate hover (8%), focus (12%), and pressed (16%) states on top of the base color.

Enabled Disabled

Disabled States

Disabled elements reduce opacity to 60% and use surface-container-high backgrounds with on-surface-low text to indicate non-interactivity.

Skeleton Loading

Skeleton screens use a shimmer animation over surface-container colors to indicate loading content while preserving layout structure.

ERR
OK
WRN
INF

Feedback Colors

Error, success, warning, and info each have base, container, and on-container token triplets that adapt to light and dark modes.

Corner Radius Progression

Components use progressively larger radii to establish visual hierarchy: inputs use small, cards use medium/large, and pills use the pill token (1000px).

Step 1Step 2Step 3

Progress & Steps

Steppers and progress bars use primary for completed states, outline-high for upcoming, with smooth transitions between each state change.
